# 廠商帳號密碼機制說明文件

## 文件資訊
- **建立日期**: 2026-01-30
- **版本**: v1.1
- **適用系統**: FTT系統 - 廠商管理模組
- **相關專案**: FTT_API, FTT_VENDER_API, FTT_VENDER_WEB

---

## 概述

本文件說明FTT系統中廠商帳號的密碼管理機制，包括登入驗證、密碼過期提醒、帳號鎖定（密碼過期、登入逾期、密碼錯誤）、解鎖等相關邏輯。

---

## 系統架構

### 涉及的專案模組
- **FTT_API**: 排程任務處理（密碼過期檢查、帳號鎖定排程）
- **FTT_VENDER_API**: 廠商API服務（登入驗證、權限檢查、密碼變更）
- **FTT_VENDER_WEB**: 廠商前端介面

### 主要資料表
- **store_vender_profile**: 廠商基本資料表
- **user_login_log**: 登入記錄表
- **tb_vender_password_history**: 廠商密碼歷史記錄表
- **tb_mailpool**: 郵件佇列表

## 帳號鎖定機制

系統具備三種自動鎖定機制：

### 1. 密碼過期鎖定機制 (90天未更換密碼)

**觸發條件**:
```sql
WHERE pw_chgtime < DateTime.Now.AddDays(-90)    -- 密碼變更超過90天
AND locked = 'N'                                -- 帳號未鎖定
```

**執行邏輯**:
1. 查詢符合條件的廠商帳號
2. 更新帳號狀態 `locked = 'Y'`
3. 記錄鎖定原因 `locked_reason = 1` (密碼90天未更換)
4. 記錄鎖定時間 `locked_time`
5. 新增密碼歷史記錄

**提醒機制**:
- **第80天**: 發送密碼變更提醒信（僅一次）
- **第90天**: 帳號自動鎖定

### 2. 登入逾期鎖定機制 (90天未登入)

**寬鬆模式邏輯**: 只有當「最後登入」AND「密碼變更」都超過90天才會鎖定帳號

**查詢邏輯**:
```sql
SELECT svp.* 
FROM store_vender_profile svp
LEFT JOIN (
    SELECT account, MAX(createtime) as last_login_time
    FROM user_login_log 
    WHERE loginstatus in ('True','TRUE')
    GROUP BY account
) ull ON svp.merchant_login = ull.account
WHERE svp.locked <> 'Y' 
  AND (
    -- 情況1: 沒有登入記錄且密碼變更時間超過90天(包含NULL)
    (ull.last_login_time IS NULL AND (svp.pw_chgtime IS NULL OR svp.pw_chgtime < NOW() - INTERVAL '90 days'))
    -- 情況2: 有登入記錄但超過90天，且密碼變更也超過90天(包含NULL)
    OR (ull.last_login_time IS NOT NULL 
        AND ull.last_login_time < NOW() - INTERVAL '90 days'
        AND (svp.pw_chgtime IS NULL OR svp.pw_chgtime < NOW() - INTERVAL '90 days'))
  )
```

**執行邏輯**:
1. 查詢符合寬鬆模式條件的廠商帳號
2. 更新帳號狀態 `locked = 'Y'`
3. 記錄鎖定原因 `locked_reason = 2` (90天未登入)
4. 記錄鎖定時間 `locked_time`
5. 新增密碼歷史記錄

**三種情境分析**:

| 情境 | 描述 | 鎖定判斷 |
|------|------|----------|
| **情境A** | 有登入但超過90天 + 密碼變更未超過90天 | ❌ 不鎖定 |
| **情境B** | 完全沒登入 + 密碼變更超過90天 | ✅ 鎖定 |
| **情境C** | 90天內有登入 + 任何密碼狀態 | ❌ 不鎖定 |

### 3. 密碼錯誤鎖定機制 (連續3次密碼錯誤)

**觸發條件**:
- 連續輸入錯誤密碼3次
- 系統會記錄每次錯誤嘗試次數於 `login_count` 欄位

**執行邏輯**:

```csharp
// 第1-2次錯誤：增加錯誤計數
if (login_count < 2) {
    base.dbHelper.Execute("UPDATE STORE_VENDER_PROFILE SET LOGIN_COUNT=LOGIN_COUNT+1 WHERE MERCHANT_LOGIN = @MERCHANT_LOGIN", paras);
}

// 第3次錯誤：鎖定帳號
if (login_count == 2) {
    base.dbHelper.Execute(@"
        UPDATE STORE_VENDER_PROFILE 
        SET LOGIN_COUNT=LOGIN_COUNT+1, 
            locked='Y', 
            locked_reason=5, 
            locked_time=@locked_time
        WHERE MERCHANT_LOGIN = @MERCHANT_LOGIN", paras);
    
    // 記錄密碼歷史
    base.dbHelper.Execute(@"
        INSERT INTO tb_vender_password_history(account, pw, createtime, locked_reason)
        VALUES (@account, @pw, @createtime, @locked_reason)", paras2);
}
```

**鎖定特性**:
- **鎖定原因**: `locked_reason = 5` (密碼輸入錯誤)
- **自動解鎖**: 15分鐘後可重新嘗試登入
- **手動解鎖**: 透過密碼變更功能立即解鎖

## 解鎖機制

### 1. 自動解鎖 (僅適用密碼錯誤鎖定)

**條件**: 
```csharp
// 密碼錯誤鎖定且超過15分鐘
if (locked_reason == 5 && locked_time.AddMinutes(15) < DateTime.Now)
{
    // 允許重新嘗試登入，但帳號仍處於鎖定狀態
    // 需要正確登入才會完全解鎖
}
```

**顯示訊息**:
- **15分鐘內**: "您的FTT帳號因密碼輸入錯誤被鎖定，請等待約X分鐘後再試，或直接進行密碼變更。"
- **15分鐘後**: "您的FTT帳號因密碼輸入錯誤被鎖定，但已可重新嘗試登入。如仍無法登入，請聯繫系統管理員。"

### 2. 成功登入解鎖

**條件**: 輸入正確密碼登入成功

**執行邏輯**:
```csharp
if (VerifyPassword(MERCHANT_PASSWORD, inputPassword)) {
    // 清除錯誤計數
    base.dbHelper.Execute("UPDATE STORE_VENDER_PROFILE SET LOGIN_COUNT=0 WHERE MERCHANT_LOGIN = @MERCHANT_LOGIN", paras);
    
    // 登入成功，建立Session
    logLoginStatus = true;
    boolIsAuthenticated = true;
}
```

### 3. 密碼變更解鎖

**適用範圍**: 所有類型的帳號鎖定

**執行邏輯**:
```csharp
// 更新密碼並解鎖帳號
string update_SQL = @"UPDATE store_vender_profile SET 
    merchant_password = @pw, 
    locked = @Locked,                    -- 設為 'N' 解鎖
    locked_reason = @LockedReason,       -- 改為 4 (廠商主動變更密碼)
    is_pwchange_remind = NULL,           -- 清除提醒狀態
    pw_chgtime = @Now,                   -- 更新密碼變更時間
    login_count = 0,                     -- 清除錯誤計數
    lasturltime = null, 
    lasturlkey = null,
    locked_time = null,                  -- 清除鎖定時間
    geturltime = null
    WHERE merchant_login = @AC";

Dictionary<string, object> paras_Update = new()
{
    { "pw", newHashedPassword },
    { "Locked", "N" },                                    // 解鎖
    { "LockedReason", (int)LockReasonEnum.ChangePwByVender },  // locked_reason = 4
    { "Now", DateTime.Now},
    { "AC", account }
};
```

**密碼歷史記錄**:
```csharp
// 同時記錄到密碼歷史表
```

## 登入驗證流程

### 1. 帳號狀態檢查順序

1. **帳號是否存在**
2. **帳號是否被鎖定** (`locked = 'Y'`)
3. **檢查鎖定原因** (如果被鎖定)
4. **密碼是否正確** (如果未鎖定)
5. **記錄登入狀態**

### 2. 鎖定狀態處理

**鎖定原因代碼對照**:
```csharp
switch (locked_reason) {
    case 1: // 密碼90天未更換
        errorMsg = "您的FTT帳號已被鎖定，原因：密碼90天未更換，請直接進行密碼變更。";
        break;
        
    case 2: // 90天未登入
        errorMsg = "您的FTT帳號已被鎖定，原因：90天未登入，請直接進行密碼變更。";
        break;
        
    case 5: // 密碼輸入錯誤鎖定
        if (locked_time.AddMinutes(15) >= DateTime.Now) {
            var remainingTime = locked_time.AddMinutes(15) - DateTime.Now;
            var minutes = (int)remainingTime.TotalMinutes + 1;
            errorMsg = $"您的FTT帳號因密碼輸入錯誤被鎖定，請等待約{minutes}分鐘後再試，或直接進行密碼變更。";
        } else {
            errorMsg = "您的FTT帳號因密碼輸入錯誤被鎖定，但已可重新嘗試登入。如仍無法登入，請聯繫系統管理員。";
        }
        break;
}
```

## 郵件通知機制

### 1. 密碼過期提醒郵件

**觸發時機**: 密碼變更後第80天

**模板位置**: `FTT_API/MailTemplate/RemindChangePW.json`

**變數替換**:
- `{{VendorName}}`: 廠商名稱
- `{{ResetPasswordUrl}}`: 密碼重設連結

### 2. 郵件發送流程

1. 產生唯一的重設金鑰 (GUID)
2. 更新廠商資料中的 `LastUrlTime` 和 `LastUrlKey`
3. 建立重設URL: `{BaseUrl}/ChangePw/Change?tempid={key}`
4. 將郵件加入發送佇列 (`tb_mailpool`)

**URL有效期**: 預設2天（可透過 `LastURLValidityperiod` 設定調整）

## 時間精確度說明

### 關鍵時間計算

**問題**: 時間比較基於精確的時間戳記，而非日期

**範例**:
- 密碼變更時間: `2025-11-01 14:30:00`
- 排程執行時間: 每日 `01:00:00`
- 第90天: `2026-01-30`

**實際觸發時間**:
- `2026-01-30 01:00:00` 執行排程時，尚未滿90天
- 直到 `2026-01-30 14:30:01` 之後才會觸發鎖定

**結論**: 系統**不會**在第81-89天之間誤觸發鎖定，只會在真正超過90天後執行。

## 測試方法

### 1. 測試函數

```csharp
public void TestCheckLastLoginTime()
```

**功能**: 只查詢應該被鎖定的帳號，不實際執行鎖定操作，用於驗證邏輯正確性。

### 2. SQL驗證查詢

#### 密碼過期機制驗證

```sql
-- 80天提醒條件驗證
SELECT * FROM store_vender_profile 
WHERE pw_chgtime < NOW() - INTERVAL '80 days'
  AND pw_chgtime > NOW() - INTERVAL '90 days'
  AND locked = 'N'
  AND (is_pwchange_remind IS NULL OR is_pwchange_remind <> 'Y');

-- 90天鎖定條件驗證
SELECT * FROM store_vender_profile 
WHERE pw_chgtime < NOW() - INTERVAL '90 days'
  AND locked = 'N';
```

#### 登入逾期機制驗證

```sql
-- 驗證寬鬆模式查詢邏輯
SELECT 
    svp.merchant_login,
    svp.merchant_name,
    svp.locked,
    svp.pw_chgtime,
    ull.last_login_time,
    CASE 
        WHEN ull.last_login_time IS NULL THEN '從未登入'
        WHEN ull.last_login_time < NOW() - INTERVAL '90 days' THEN '登入超過90天'
        ELSE '登入未超過90天'
    END as login_status,
    CASE 
        WHEN svp.pw_chgtime IS NULL THEN '密碼NULL'
        WHEN svp.pw_chgtime < NOW() - INTERVAL '90 days' THEN '密碼超過90天'
        ELSE '密碼未超過90天'
    END as pw_status
FROM store_vender_profile svp
LEFT JOIN (
    SELECT account, MAX(createtime) as last_login_time
    FROM user_login_log 
    WHERE loginstatus in ('True','TRUE')
    GROUP BY account
) ull ON svp.merchant_login = ull.account
WHERE svp.locked <> 'Y'
ORDER BY svp.merchant_login;
```

#### 密碼錯誤機制驗證

```sql
-- 檢查錯誤計數和鎖定狀態
SELECT 
    merchant_login,
    login_count,
    locked,
    locked_reason,
    locked_time,
    CASE 
        WHEN locked_reason = 5 AND locked_time > NOW() - INTERVAL '15 minutes' THEN '仍在鎖定期間'
        WHEN locked_reason = 5 AND locked_time <= NOW() - INTERVAL '15 minutes' THEN '可重新嘗試'
        ELSE '非密碼錯誤鎖定'
    END as lock_status
FROM store_vender_profile 
WHERE locked = 'Y' AND locked_reason = 5;
```

## 安全性考量

### 1. 密碼儲存

- 使用雜湊演算法儲存密碼，不儲存明文
- 密碼歷史記錄同樣使用雜湊儲存

### 2. 防暴力攻擊

- 3次錯誤密碼自動鎖定
- 15分鐘冷卻期
- 錯誤次數記錄於資料庫

### 3. URL安全性

- 密碼重設URL使用GUID，難以猜測
- URL具有時效性（預設2天）
- 使用後自動清除金鑰

系統會記錄以下除錯資訊:
- 總未鎖定廠商帳號數量
- 密碼變更超過90天的帳號數（包含NULL）
- NULL密碼變更時間的帳號數
- 成功登入記錄的帳號數
- 最終查詢結果數量

### 2. 錯誤日誌

**記錄位置**: `TB_Control_Log` 表
**記錄內容**: 
- 控制器名稱
- 動作名稱  
- 異常訊息
- 執行狀態

## 測試方法

### 1. 測試函數

```csharp
public void TestCheckLastLoginTime()
```

**功能**: 只查詢應該被鎖定的帳號，不實際執行鎖定操作，用於驗證邏輯正確性。

### 2. SQL驗證查詢

可使用以下SQL直接驗證資料：

```sql
-- 驗證密碼變更條件（包含NULL）
SELECT COUNT(*) as pw_over_90days_including_null
FROM store_vender_profile 
WHERE locked <> 'Y' 
  AND (pw_chgtime IS NULL OR pw_chgtime < NOW() - INTERVAL '90 days');

-- 檢視應該被鎖定的帳號詳細資料
SELECT 
    svp.merchant_login,
    svp.merchant_name,
    svp.locked,
    svp.pw_chgtime,
    ull.last_login_time
FROM store_vender_profile svp
LEFT JOIN (
    SELECT account, MAX(createtime) as last_login_time
    FROM user_login_log 
    WHERE loginstatus in ('True','TRUE')
    GROUP BY account
) ull ON svp.merchant_login = ull.account
WHERE svp.locked <> 'Y' 
  AND (
    (ull.last_login_time IS NULL AND (svp.pw_chgtime IS NULL OR svp.pw_chgtime < NOW() - INTERVAL '90 days'))
    OR (ull.last_login_time IS NOT NULL 
        AND ull.last_login_time < NOW() - INTERVAL '90 days'
        AND (svp.pw_chgtime IS NULL OR svp.pw_chgtime < NOW() - INTERVAL '90 days'))
  )
ORDER BY svp.merchant_login;
```
